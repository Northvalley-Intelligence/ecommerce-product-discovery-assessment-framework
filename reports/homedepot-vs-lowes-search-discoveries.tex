{\fontsize{8.4}{10.4}\selectfont\itshape\color{NVIMuted}\textbf{Disclaimer:} quick, exploratory analysis for rapid personal research --- nowhere near complete, not verified, and not to be cited or referenced. The \textbf{approach itself is sound and can be made production-reliable} given retailer API access, real query logs (actual search terms), and higher volume; the current numbers rest on small per-query samples and browser-read counts.}\par
\vspace{0.10in}
\begin{minipage}[t]{0.64\linewidth}
\ReportDarkCard{The Headline}{Home Depot and Lowe's are near-tied on core relevance, but they fail in opposite, fixable ways. Lowe's wins on synonyms; Home Depot edges project search; and both mishandle industry specs --- Home Depot ignores them, Lowe's over-reacts to them.}
\vspace{0.12in}
\ReportBody{We evaluated live on-site search on \textbf{homedepot.com} and \textbf{lowes.com} across three query datasets: (1)~\textbf{synonym/category} equivalence, (2)~\textbf{dimensions} --- measurement notation and the ``\#'' spec gradations, and (3)~\textbf{pro/job-function} project and trade queries. Results were captured by bounded, same-origin browser reads (no crawling or scraping); result counts read deterministically; and each returned product graded 0--3 for relevance by a local LLM judge, scored as NDCG. The three headline numbers are at right.}\par
\vspace{0.12in}
\ReportSection{What This Answers}
\begin{itemize}
\item Which engine returns more relevant results, and where does each break?
\item Do the engines understand industry specs (``\#57 stone'', ``\#4 rebar'') and notation (``1/2-in'')?
\item Which is better for natural-language project shopping (``build a deck'')?
\end{itemize}

\ReportPageHeader{Findings}
\ReportFooter
\ReportSection{Key Findings}
\begin{minipage}[t]{0.48\linewidth}
\FindingBlock{Finding 01}{Industry specs are the biggest gap}{The ``\#'' gradations (\#57 stone, \#4 rebar, \#7 drill bit) are hard catalog specs. \textbf{Home Depot ignores them} --- it returns generic in-category products and never surfaces the true spec. \textbf{Lowe's over-reacts} --- it treats the ``\#'' as a different query and often derails to the wrong category entirely. Neither reliably finds the exact spec'd item.}
\vspace{0.10in}
\FindingBlock{Finding 02}{Notation fails oppositely}{Home Depot breaks on \textbf{hyphenation}: ``1/2-in screw'' drops about 70\% of the results of ``1/2 in screw'' --- a recall cliff. Lowe's breaks on \textbf{unit words}: ``10 foot cable'' returns a fraction of ``10 ft cable''. Relevance of what each keeps stays high, so these are recall failures, not ranking failures.}
\vspace{0.10in}
\FindingBlock{Finding 03}{Project intent isn't routed to project pages}{Both retailers \textbf{publish curated project / job-function pages} (Home Depot's ``build a deck'' project guide), but search does \textbf{not recognize the project intent and route to them} --- it returns a generic product list instead. The content already exists; search simply does not connect the query to it. Home Depot also monetizes ``install a\ldots'' as paid services; both fail bare trade names (``electrician'', ``landscaper'' return \textbf{zero products}).}
\end{minipage}
\hfill
\begin{minipage}[t]{0.46\linewidth}
\ReportCard{Business Implication}{These are not vague ``search feels off'' complaints --- each is a specific, reproducible query behavior with a clear fix. Spec parsing and notation normalization are self-contained engine changes; synonym coverage is a mapping problem. All three convert directly into found products, fewer dead-ends, and larger baskets.}

\ReportPageHeader{Appendix — Method and Scores}
\ReportFooter
\ReportSection{Appendix A — Relevance Judge}
\ReportBody{Every returned product was graded 0--3 for relevance to the query intent by \textbf{Meta Llama 3.2 3B} (model \texttt{llama3.2:3b}), run \textbf{locally} via Ollama and orchestrated by the Cortex evaluation service at \textbf{temperature 0} (deterministic; re-runs are stable). Grades: 3 = perfect match, 2 = relevant, 1 = marginal, 0 = irrelevant. Per-query \textbf{NDCG} (0--1) discounts by rank, so a mis-ordered or partly-irrelevant top set scores lower. Every grade is a stored, inspectable trace of the exact prompt and model output. The judge was validated against a hand-labelled gold set (12/13) and two notation defects were fixed before scoring. A ``\textemdash{}'' below means the query returned no products (or was not captured) on that retailer. The synonym dataset is scored by result-count consistency, not LLM NDCG, so it is not listed here.}\par
